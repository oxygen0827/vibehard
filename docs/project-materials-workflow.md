# 项目资料配套与统一工作入口

2026-09-30：第一阶段本地实现并纳入本地提交，尚未推送、部署或进行真实模型/硬件验收。分支 `codex/project-materials-workflow`，沿用干净隔离工作树，不改主工作区未提交内容。

## 用户路径

1. 方案任务完成后，查看「方案资料配套检查」。对每条 BOM 分别显示「找到型号参考」「本次证据未覆盖」「型号待明确」。检查记录随新方案结果保存，不额外调用模型、不增加检索请求，原有 90 秒总预算不变。
2. 从方案记录或 Agent 项目概览下载「项目资料包 ZIP」。这是与指定方案绑定的小型参考包，不是已生成固件，也不含全部 OSS 原件。
3. Agent 回合启动前，已有 `project-design-files-v1` 归档链路将方案、BOM、来源摘录和检查清单作为同一 Markdown 校验落盘到 `designs/`。本轮无需扩展 Runner 协议。原理图资料继续使用 `documents/`。
4. Agent 项目、AI 调试、嵌入式开发共用一个工作台。顶部选择项目，模块间链接带同一项目 ID；查看相同会话、审批、产物。任务模板只预填，不自动调用模型或操作设备。切换项目清空未发送任务，错误项目 URL 不再静默回退到其他项目。

## 检查口径与未完成范围

首版只检查**生成时实际返回的最多 5 条检索证据**，不是按每个器件重新搜索全库，也不是完整配套资料收集器。检索之前模型尚未给出最终 BOM，因此缺项很正常，不能把缺项称为全库不存在。

- 只接受单一完整型号，在标题/文件名中精确匹配；不根据父目录、正文随意提及、型号前缀或模糊别名关联。多个候选、同类、系列、型号未明确均提示先确认。宁可漏配待补，不把 RV1126B 资料匹配给 RV1126，或把芯片系列手册称为具体开发板原理图。
- 手册/原理图/引脚/驱动分类依据标题和文件名；仍需核对全文。精确名称命中不证明封装、板卡版本、引脚、电气参数正确，也不表示全部资料齐全。
- 保留自动索引「未人工复核」、已发布、部分知识不可用等标识。模型自己提交的 `materials`、`retrieval` 字段在 Worker 解析阶段丢弃，由服务端生成检查和引用。
- 历史结果无检查字段，不回填、不重新渲染新增报告，不改变原方案 Markdown/哈希。
- 检索来源 SHA256 是服务记录的来源/知识版本哈希，不一概视作 PDF 原件哈希；ZIP 内每个文件另有内容哈希。
- 下一阶段：受控逐器件补检索与版本锁定、可撤销的项目参考资料缓存（不能把历史摘录当作永不过期授权）、设备绑定及执行闭环。本轮没有实现跨云端/USB Runner 自动路由，也没有修改原理图识别精度。

## 资料包结构

```text
project-materials-<designId>.zip
├── README.md
├── requirements.md
├── designs/design.md
├── bom.csv
├── materials/check.md
├── references/source-01.md ... source-05.md
└── manifest.json
```

清单固定路径、项目/方案 ID、逐文件字节数与 SHA256、来源 ID/版本/来源位置/哈希/审核标识；不接受模型指定文件路径。原图/手册原件继续私有保存在 OSS。解压前总文本限制 512 KiB，ZIP 时间元数据固定，同一输入同一版本重复打包一致。历史价格沿用既有逻辑：未保存当时价格的旧方案显示当前参考报价。

下载接口 `GET /api/design/:id/materials` 复用现有登录与 `getDesign` 双归属查询；匿名 401、错误 ID 400、不存在/他人方案 404、未完成 409、存储/打包失败 503。成功响应 `private, no-store`，不暴露 OSS 凭据或新增原件访问入口。没有新增数据库迁移；检查保存在既有 result JSON 内。

## 验收表

| 模块 | 真实输入 | 实际执行 | 持久结果 | 失败提示 |
| --- | --- | --- | --- | --- |
| 方案配套 | 解析后的 BOM＋服务端检索证据 | 确定性型号对应与来源分类，无二次 LLM | 随任务 result JSON、Markdown 保存 | 模型不明确/证据未覆盖/部分知识不可用 |
| 资料包 | 当前账号拥有的已完成方案 ID | 固定路径 ZIP 打包、文件哈希 | 源任务不改写，用户可下载 | 权限/未完成/存储/容量失败 |
| AI 调试 | 选项目＋明确发送任务 | 共用真实 Agent 任务接口与事件流 | 沿用会话、审批、项目产物 | 服务端错误显示，不能用计时器模拟成功 |
| 嵌入式开发 | 同项目资料＋需求 | 共用真实 Agent 分析/受控修改流程 | 同上；并非自动生成固件 | 缺源码/资料/工具链须据实反馈 |
| 实机设备 | 尚需明确设备绑定及操作 | 本轮未执行 USB/串口/烧录 | 未验证 | 云端项目不能因插 USB 自动操作本地板 |

## 本地验证与发布门槛

- 单元/组件：精确型号、错后缀、同类、多候选、正文与目录误匹配、模型伪造报告、无额外计费请求；ZIP 固定结构、文件/来源哈希、容量、历史兼容；下载授权入口与失败响应；两个模块同项目/明确发送/不自动调用、错误 URL、切换清空输入。
- 真实子进程：现有 Runner 实际写方案文件，测试 Agent 子进程 `readFileSync` 读到配套报告和来源校验文本后才完成。Agent/LLM 为替身，不是云端模型或硬件验收。
- 常规回归 406 通过、22 条件跳过；TypeScript、定向 ESLint、网页及服务构建通过。独立 PostgreSQL 测试已补断言，但本机没有可用 PostgreSQL/Docker，未执行。未运行指向云端隔离库的旧脚本以遵守本轮本地范围。
- 浏览器：本机内存预览合成账号/项目，验证项目下拉、调试任务预填、跨模块项目保持、复用会话、消息/输入区域。在当时 653×1100 视口无整页或横向溢出；未点击真实任务发送。无数据库时资料/方案读取明确失败，不能当作端到端验收。
- 上线前须在隔离数据库跑新增/既有持久化及双账号测试，再用真实模型完成「生成 → 检查 → ZIP → Agent 实际读取」验收。随后配套发布网页＋design worker，保留 PCB/Demo/EDA 与既有 Runner 能力；无需轮换凭据或迁移数据库。生产验证和上线需要后续授权。

当前先复用现有方案载荷完成第一阶段，没有采用先前待确认的 Runner 协议扩展；后续设备跨节点链路仍须独立设计、确认和验收。
