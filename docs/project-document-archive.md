# 统一项目选择与原理图资料归档

状态：2026-09-30 13:30，已发布 `20260930-project-archive-v1`，完成隔离及正式公网真实 OSS/模型/Agent 工具读取验收，详见 [发布记录](release-project-archive-20260930.md)。

## 本轮范围

用户要求先打通「选项目 → 原理图识别 → 自动归档 → Agent 实际读取文件」。仅连接 Agent 项目与原理图识别，不改识别精度、不接入设备操作，不把私人识别草案自动发布到公共知识库。使用独立工作树 `codex/agent-project-ux`，保留主工作区未提交内容。

## 用户怎么操作

1. 在 Agent 项目创建或选中项目，点击项目概览的「项目资料 → 添加原理图资料」。链接会携带该项目；也可在原理图识别页面用「当前项目」下拉选择。
2. 上传图纸并确认有权处理、允许私有保存与模型识别，再点击「开始识别」。分析期间锁定项目，避免存错位置。
3. 成功后出现「已自动归档」和固定文档路径。返回该项目，能看到资料状态，并下载原图或分析 Markdown；刷新、离开页面不会删除已完成的归档。
4. 点击「让 Agent 分析项目资料」进入/复用会话并预填任务，用户确认发送。Runner 在启动模型前校验并落盘，Agent 收到必须读取这些文件的指引；真实读取证据看工具日志，不把“已同步”当成“已读懂或验证”。

页面跳转通过 `?project=<id>` 传递项目；下拉只接受当前账号项目列表中的 ID，不依赖跨账号共享的 localStorage。服务端仍逐请求核验归属，URL 不是授权凭证。

## 数据放在哪里

| 内容 | 权威保存位置 | 访问方式 |
| --- | --- | --- |
| 原始图片/PDF | 私有 OSS，`projects/raw/v1/<user>/<project>/<document>/<sha256>` | 所有者登录后由后端校验并下载，不向浏览器暴露密钥、Object Key 或公开链接 |
| 识别结果、来源、失败与同步状态 | PostgreSQL `project_documents`，增量迁移 `0009_project_documents.sql` | 本项目只读资料接口；AI 草案不等同于已审核知识 |
| Agent 可读 Markdown | 本项目 Runner 工作目录 `documents/` | 每次任务开始前验证内容 SHA256，缺失则创建；已有同名不同内容时拒绝覆盖 |

```text
项目工作目录/
├── designs/                    # 既有方案文件
└── documents/
    └── schematic-<documentUUID>-<sha256前16位>.md
```

目录和文件名由代码决定，不能由模型或上传文件名指定。Markdown 含原图 SHA256、分析编号、模型、时间及未复核声明；原图不重复复制进 Runner。同步后的 Markdown 可包含在项目 ZIP 中，原图从项目资料页独立下载。

归档仅为私有项目参考。用户另点「申请加入知识库备选」才进入既有审核流程，最终发布权限仍为管理员/开发者。未人工复核的识别内容不能宣称电气参数或硬件已验证，资料内的操作指令也不是 Agent 的授权。

## 失败与负载边界

- 单文件最多 5 MiB，PNG/JPG/PDF；PDF 最多 6 页。每项目最多 20 条归档尝试，包含失败记录；首版未做自助删除和无限历史。
- 必须先有持久数据库、模型配置及 OSS 配置。先预留记录、写入原图，再请求模型；OSS 出错不得调用模型或显示成功。
- 同一请求 ID 重放完成结果，不再请求模型；处理中或失败会明确提示查看记录/重新选择文件，不自动重试计费。记录 ID 与项目/原图哈希绑定。
- 状态为 `processing → completed/failed`。这不是持久后台识别队列：浏览器中断会尝试取消识别；模型已返回后继续保存。进程意外退出可能留下处理中记录，须检查后手动重新发起，不能自动当作完成。
- 原理图识别每进程最多 2 个并发、每用户每分钟 3 次；原图下载每进程 2 并发、每用户每分钟 20 次。原图下载有大小/SHA 校验，失败返回 503，繁忙返回 429。
- 模型请求仍限 90 秒，网页等待 150 秒包含上传、PDF 转图、OSS 与保存时间；不改方案生成任务的 90 秒预算。
- 每份下发 Markdown 最多 24 KiB，单次全部资料 JSON 最多 512 KiB。不会扫描全部 OSS 或把原图全量塞进上下文。
- Runner 需声明 `project-documents-v1` 且心跳新鲜。旧 Runner 对没有新归档的项目仍兼容；有归档但 Runner 不支持时返回明确 409，不能继续使用空目录。任务接收与连接中断仍沿用既有命令队列/租约机制，心跳本身不等于任务成功。
- 新资料使归档 revision 改变，下一轮不沿用旧 native Agent 上下文，避免继续认为项目为空。旧对话与文件仍保留。
- `syncedAt` 只接受与服务端派发的项目、资料 ID、路径、SHA 一致的 Runner 回执。表示曾同步成功，不代表文件之后不会被用户修改；每轮仍检查文件。

## 配置与上线前门槛

网页后端使用 `OSS_PROJECT_BUCKET/REGION/ACCESS_KEY_ID/ACCESS_KEY_SECRET`，未设置时可回退到相应 `OSS_KNOWLEDGE_*`。可选 `OSS_PROJECT_STS_TOKEN` 只支持当前有效临时凭证，尚未实现自动刷新。配置示例在 `.env.example`，真实凭据不得提交。

可沿用现有 bucket，但需检查该服务身份有上述项目前缀的 PUT、HEAD、GET 权限及私有对象 ACL 权限。后端使用 HTTPS/V4 签名和不可覆盖写入；不得改为公共读来绕过权限问题。OSS SDK 与密钥只进入网页后端，不进入 Runner、浏览器或 Gateway。

本次已获上线授权并通过以下门槛；后续发布仍须按项目规范操作：

1. 核对现网发布清单、备份数据库、检查容量与活跃任务。在隔离候选库执行 0009，使用专用验收账号/项目与合成图纸验证真实 OSS 和当前视觉模型。
2. 发布支持新可选载荷的 Runner；更新 Gateway 的事件入库代码以记录受校验的资料同步回执。旧 Gateway 可透传 `task.start`，但不能证明资料已同步，所以不能只更新网页。无需重注册/轮换 Runner credential。
3. 生产增量迁移后再切换网页，等待新鲜 Runner 心跳与活连接；真正发送一个 Agent 回合，在工具日志确认读取 `documents/`，核对原图和 Markdown 哈希、下载 ZIP。
4. 对第二账号验证不能列出、识别入库、下载或获得别人项目载荷；检查 OSS 故障、旧 Runner、同请求重放不重复计费。执行完整前端保护检查，保留 PCB、Demo、EDA 和其他已发布功能。

`scripts/verify-schematic-http.mjs` 已改为专用验收账号正常登录，需要明确测试项目和双开关；会产生原图/识别结果并消耗一次模型调用，不可无授权在生产运行。脚本不再读取生产用户密码哈希或伪造会话。
