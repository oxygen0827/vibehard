# 方案交接到 Agent 工作区

状态：2026-09-29 已发布到 `20260929-integrated-agent-eda-v2`。

本轮验证：初版 317、整合后 358 常规测试通过；15 项真实隔离 PostgreSQL 专项通过；类型、网页和服务构建通过。包含跨账号/Runner、伪造回执、错误哈希/符号链接、文件并发幂等与编辑保留、工程 ZIP 回读。生产 5 份历史方案及 1 份合成验收方案全部落盘并核对哈希；公网真实模型工具读到合成方案校验码，下载 ZIP 含相同文档，跨账号 403。浏览器自动化超时，未做生产登录态人工点击；折叠交互由组件测试验证。详见 [整合发布记录](release-integration-20260929.md)。

## 原因与新行为

此前方案需求和结果只保存在 PostgreSQL `design_jobs`，项目目录由 Runner 首次执行时创建，因此进入 Agent 后实际是空目录。

云端 Runner 现在每 15 秒向受身份验证的同步接口读取一页（最多两份）尚未确认的已完成方案，按源文件哈希校验并原子落盘到 `designs/方案-<任务 UUID>-<哈希前 16 位>.md`。完成后才登记项目产物；历史方案使用相同流程补齐。数据库保存的需求、结果和引用仍为源记录，无新增数据库迁移。

每次 Agent 回合选择本项目最新完成的方案，并将有界载荷附在 `task.start`。Runner 在调用模型前再次校验/补写该文件，明确提供路径与方案分析说明。检索查询也包含原方案需求。新方案与上一轮哈希不同时重建模型上下文，网页历史消息保留。方案文本是参考数据，不被提升为指令或已验证工程事实；不自动进入知识库。

## 隔离与兼容

- 同步接口只接受 `cloud-runner` 的有效凭据，只读取分配给该 Runner 且项目/方案所有者一致的已完成记录。
- 每份 Markdown 最大 128 KiB；单页两份，轮询不重入，12 秒网络预算。单文件失败继续分页，下轮补偿；不会触发付费模型调用。
- 路径由方案 UUID 和哈希生成，不接受浏览器指定路径。原子发布、不覆盖不同内容；拒绝目录/文件符号链接，Linux 写入固定目录描述符。
- `project-design-files-v1` 为可选能力；有方案但 Runner 不支持时明确报错，避免继续发送空工作区。无方案的旧项目保持兼容。
- 方案文件是草案文档，不能称为已生成可编译固件。已有工程代码、用户编辑和旧方案保留。

## 发布与回滚

需要发布平台和云端 Runner；方案 Worker、数据库结构与 Gateway 协议版本不变。先发布含新接口的平台并在无活跃任务时更新 Runner，确认能力和心跳后再做真实对话验收。混合版本期间有方案的任务会明确提示执行器待更新。

生产验收应确认：旧方案自动落盘/产物可见、再次发送“分析方案”能实际读到文件、项目下载包含 Markdown、新方案更新后不会沿用旧上下文、跨项目拒绝、已有工程文件不变。回滚平台和 Runner 到对应旧包即可；已生成文档保留，不回滚数据库或删除项目文件。
