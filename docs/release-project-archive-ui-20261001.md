独立分支基于默认 `399f5f1`，保留主工作区及归档功能的未提交修改。先评审/CI、完整保护源码清单校验、候选 PCB/Demo/BOM/匿名边界，再备份和零活跃任务切换；仅网页服务重启。候选端口 3217，避免占用尚待真实账号验收的隔离候选 3211。

发布前后必须核对六个其他服务与 nginx 的 PID/配置不变、云端 Runner 新鲜心跳及两条真实 Gateway 连接。数据库备份只用于事故恢复，不覆盖新用户数据。

## 回滚

## 证据

最终本地 448 项常规测试通过、30 项环境条件测试跳过；15 项定向交互测试、TypeScript、定向 ESLint、发布脚本语法及 `/vibehard` 生产构建通过。隔离数据库测试由 CI 单独运行。已手工评审 UI diff，确认设备组件实际不挂载，而非仅 CSS 隐藏；调试/开发仍使用原控件，旧报告不删除。

本机空间不足时，仅清理本轮失败的 v1 候选目录/压缩包（约 576 MiB）和本工作树可重建构建缓存（312 MiB），保留 v2 候选包、验收脚本与所有正式/用户数据。Git LFS 内部检查重跑通过。

首个 PR 版本 CI 全部通过，但云端 v1 候选发现 standalone 顶层依赖目录是本机共享 node_modules 的绝对链接，启动失败，未激活正式环境。改为独立依赖目录重新构建，并新增本地打包/云端发布双侧 portable-link 门禁及三个链接回归测试（绝对路径、相对逃逸、悬空链接拒绝）。新的不可变版本为 `20261001-project-archive-ui-v2`，不覆盖已解包的失败候选。

v2 候选启动成功，PCB/18 资源/5 GIF/匿名鉴权通过，但既有 BOM 验证器仅允许 3210/3211，拒绝本轮隔离端口 3217。验证器仅增加该回环端口，并用真实本地 HTTP 与子进程测试全部四项鉴权检查仍执行、其他端口仍拒绝；没有跳过 BOM 门槛。最终不可变包改为 v3，正式服务仍未切换。

v3 完整网页/BOM 门禁通过后，额外 Linux PDF 实际渲染复现缺失：构建的顶层 pdfjs 目录只有 worker/字体等资源，主文件实际在 `.pnpm` 中，顶层目录挡住依赖入口。本机还会错误回落到开发依赖，因此保留实际解析路径必须位于 standalone 的检查。新增“只有 worker 的目录必须拒绝”回归先失败，再修正打包：物化完整现有锁定版本 pdfjs，不升级依赖；本机包与云端候选都必须通过真实 PDF 像素渲染后才能记为通过。最终不可变包 v4；候选 3217 重建，正式环境未受影响。
