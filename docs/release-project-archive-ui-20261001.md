# Agent 项目与设备操作入口分离发布

2026-10-01，用户明确要求上线本次模块分工调整。

## 范围

- Agent 项目不挂载 USB 连接组件，项目不限定 RV1126B；保留已有资料、方案、会话、产物、报告与下载。
- AI 调试和嵌入式开发保留当前项目的 USB 只读报告入口，独立设备开发保持。跨模块跳转继续带上项目 ID。
- 仅运行时 `components/app/agent-workbench.tsx`、`lib/module-help.ts` 改动；数据库、权限、Runner/Gateway、检索、知识原件、模型配置和设备实现不变。
- 新的 VibeBoard 开发结果关联与版本归档仍在独立 `codex/embedded-project-archive`，真实来源账号验收未完成，不包含在本次发布中；本次不迁移 0010，不展示尚未发布的应用关联/同步控件。

## 发布门槛

独立分支基于默认 `399f5f1`，保留主工作区及归档功能的未提交修改。先评审/CI、完整保护源码清单校验、候选 PCB/Demo/BOM/匿名边界，再备份和零活跃任务切换；仅网页服务重启。候选端口 3217，避免占用尚待真实账号验收的隔离候选 3211。

发布前后必须核对六个其他服务与 nginx 的 PID/配置不变、云端 Runner 新鲜心跳及两条真实 Gateway 连接。数据库备份只用于事故恢复，不覆盖新用户数据。

## 回滚

使用既有平台/EDA 环境，运行新 release `source/scripts/deploy-project-archive-ui.mjs rollback`。脚本先核对零活跃任务与当前版本，仅恢复备份的平台 unit，不回滚数据库或重启设备/Runner。

## 证据

本地 443 项常规测试通过、30 项环境条件测试跳过；15 项定向交互测试、TypeScript、定向 ESLint、发布脚本语法及 `/vibehard` 生产构建通过。隔离数据库测试由 CI 单独运行。已手工评审 UI diff，确认设备组件实际不挂载，而非仅 CSS 隐藏；调试/开发仍使用原控件，旧报告不删除。

本机空间不足时，仅清理本轮失败的 v1 候选目录/压缩包（约 576 MiB）和本工作树可重建构建缓存（312 MiB），保留 v2 候选包、验收脚本与所有正式/用户数据。Git LFS 内部检查重跑通过。

首个 PR 版本 CI 全部通过，但云端 v1 候选发现 standalone 顶层依赖目录是本机共享 node_modules 的绝对链接，启动失败，未激活正式环境。改为独立依赖目录重新构建，并新增本地打包/云端发布双侧 portable-link 门禁及三个链接回归测试（绝对路径、相对逃逸、悬空链接拒绝）。新的不可变版本为 `20261001-project-archive-ui-v2`，不覆盖已解包的失败候选。

v2 候选启动成功，PCB/18 资源/5 GIF/匿名鉴权通过，但既有 BOM 验证器仅允许 3210/3211，拒绝本轮隔离端口 3217。验证器仅增加该回环端口，并用真实本地 HTTP 与子进程测试全部四项鉴权检查仍执行、其他端口仍拒绝；没有跳过 BOM 门槛。最终不可变包改为 v3，正式服务仍未切换。

修正后的 CI、候选及实际发布证据待补。没有本轮新的付费模型请求或硬件读写验收，不据此宣称设备闭环已完成。
