## 两种资料来源

1. 网页上传原理图，真实模型生成带来源/待确认项的分析 Markdown，由用户选择项目并申请进入备选；本轮实现。
2. 既往板卡开发经验 Markdown，由用户/开发者/管理员提供，先经 Agent 整理（板卡及版本、前提、操作、验证证据、失败原因、可复用结论、未知项），再进入备选；本轮未实现这个专用处理通道。现有知识页的手工草稿/MD 导入仍存在，不应误称为已经自动经 Agent 整理。

“备选”就是项目内待审核草稿。9/20 新规则：用户只能申请，只有平台管理员或开发者显式审核发布才进入 Agent 的正式快照；不新增全平台公共知识库或自动发布。审核角色只能跨项目查看和审核知识，不能编辑他人草稿或读取其聊天/工程。

## 用户点击位置

1. 左侧「原理图识别」，先在「当前项目」选择所属项目，上传 PNG/JPG/PDF，勾选有权处理且同意私有保存/模型识别，点击「开始识别」。可从 Agent 项目概览「添加原理图资料」带入同一项目。
2. 成功后的「识别结果 · 待审核」区域右上角可「下载识别文档 MD」。正文下方是「申请推送到知识库备选」。
3. 成功结果已归档到选定项目，并显示文档路径；点击「申请加入知识库备选」另行提交该项目待审草稿。私有归档不等于正式知识发布。
4. 成功后点击「查看申请与审核状态 →」，直达该项目、该草稿。普通所有者可修改后保存，但看不到发布按钮。
5. 管理员或开发者进入左侧「平台管理 → 知识库审核」，选择资料，核对原文件后勾选确认并点击「审核并发布」，或填原因「退回修改」。这是单独权限与动作，不在申请按钮中执行。

用户没有项目时提示先创建项目；项目获取失败可重试，不把失败当成空列表。识别失败不提供申请按钮，不回退固定 STM32 示例。更换文件或重新识别清除旧结果；提交期间不能换文件/项目。下载内容包含标题、来源与同一份完整正文；以纯文本渲染，不执行 Markdown 内 HTML。

## 后端和数据边界

- `POST /api/schematic`：沿用登录认证，限每用户每分钟 3 次、每用户最多 1 个进行中任务、每个平台进程最多 2 个。部署多进程时这些限制不共享，需另建全局配额。
- 文件本体最多 5 MiB；先限流读取 multipart 请求总字节，再解析，验证文件魔数、扩展名/MIME。不是完整文件安全扫描。PDF 在内存中最多渲染 6 页，每页限制像素与输出大小，按页作为 PNG/JPG 图片发送。9/30 起原图先写私有 OSS、结果与状态写 `project_documents`；渲染图片不额外持久保存。原图只允许所属账号经校验下载。
- 暂共用 `design`（硬件方案生成）模型配置，不改变现有模型或 Key。原理图请求只向模型发送图片：Responses 使用 `input_image`，Chat Completions 使用 `image_url`；PDF 不再作为 `input_file` 直接发送。没有配置、限流、PDF 页数/渲染错误、超时或不支持图片时明确报错；模型返回 `Unsupported Document` 风格的不可读正文不生成备选草稿。
- 模型提示将正文控制在 4500 字符内（包括字母、换行和 Markdown 符号）；实际可保存长度按「知识正文 6000 字符 − 服务端待审核声明长度」计算，当前为 5952。完整保留可容纳的识别正文，不做静默截断。真正超限时显示实际长度和上限，并区分短正文、标题及字段格式错误。来源由服务端填写原文件名、SHA256、模型、时间和唯一分析编号。来源是追溯提示，不是不可伪造的签名证书；项目所有者本来就能编辑草稿。
- 无工具模型提取要求区分事实/推断/未知，注明页码/区域/位号，不补全不可见引脚、不声称 ERC/上板通过。这是提示词约束，不是识别正确性保证。
- NDJSON 心跳 10 秒、模型超时 90 秒，浏览器最长等待 150 秒（含上传、OSS、转图和保存），支持取消。无自动循环重试或后台恢复队列；同请求 ID 完成结果重放不再请求模型。
- 申请复用 `POST /api/projects/<id>/knowledge` 的 create：附 `submissionId=analysisId`。服务端在现有项目事务锁内去重，保存原始提交摘要，同一编号/内容重试不重复建档，也不覆盖后来编辑/审核状态；编号复用不同内容返回 409。申请接口本身无新迁移，9/30 的独立私有归档另有 0009 新表。
- 草稿提交/编辑仍要求项目所有权，publish/reject/disable 仅允许管理员或开发者。审核后才进入知识快照；原理图模型不直接触发云端工程 Agent，不使用任何设备/烧录工具。

## 验证

- 9/29 正文校验修复（14:10 已发布）：同一份用户 PDF 已正常转图，真实 DeepSeek Flash 返回有效 JSON，正文 5590 字符被旧 5500 上限拒绝；加服务端声明仅 5638，仍符合知识库上限。修复后回放完整通过；同图新请求 23.4 秒返回 3575 字符并通过校验。原图和模型正文只在临时复现目录使用，不提交仓库、不写正式知识。自动验收只验证传输、字段、长度和可见器件引用，未做逐引脚电气正确性验收。正式公网同图识别 51.9 秒返回 3848 字符完整草稿，见 [发布记录](release-schematic-result-20260929.md)。

- 9/20 发布：101 项常规 + 3 项隔离 PostgreSQL 测试、候选 HTTP 权限与资料生命周期、正式/公网前端保护通过。VibeHard nginx location 上传上限设为 6 MiB，保留应用 5 MiB 限制；采用保持原 inode 的配置写入和 `nginx -t` 后平滑 reload，无容器重启。公网超过 5 MiB 的请求到达应用并返回 JSON 413（非 nginx 拦截）。约 1.1 MB 及 <2 KB 合成 PDF 两次真实模型请求均 90 秒超时，未获得草稿，不能据代码上线声称识别稳定可用；浏览器连接工具超时，未完成点击全流程。
