# 逐器件补检索与项目资料版本锁

2026-09-30 22:08 已上线 `20260930-project-material-lock-v1`；功能 `b29ae71`、CI 隔离修复 `2f001f5` 经 PR #38 合并。候选/公网真实方案、Agent 工具读文件、资料锁/包哈希、权限与负载均已验收，详见[发布证据与回滚](release-project-material-lock-20260930.md)。不代表资料完整或物理硬件已验证。

## 用户流程

生成方案 → 校验最终 BOM → 按精确型号补检索 → 将资料版本锁保存到方案 → 自动归档到项目方案文件 → 新 Agent 回合核验并优先复用锁定参考。

方案页“逐器件资料与版本锁”显示各器件命中/未命中/型号待明确/未完成，来源可展开查看标题、版本、位置、SHA256、审核标识和摘录。会话中“本回合检索”显示是否复用了已核验的项目资料锁。锁失效时改用当前受控检索，不静默改写历史锁。

项目 `designs/` 文件包含逐器件清单及必要摘录；资料包 ZIP 另含 `materials/lock.json`、`materials/components.md`、`references/components/source-NN.md`。文件名由服务端生成，不由型号或来源路径决定。原件继续留在私有 OSS，不复制全部 PDF/SDK，也不把短摘录当作完整资料。

## 检索与锁定规则

- 保留完整芯片/板卡型号，不去掉封装/变体后缀，不把 `RV1126` 当作 `RV1126B`。多个候选型号先标为待明确。重复精确型号只查询一次，复用关联。
- 标题/文件名完整型号匹配；只允许去掉明确的文档类型后缀，不靠正文偶然提及或目录名来建立身份。对于 `schematic.pdf` 等通用文件名，仅私有索引中已校验的不可变板卡关联可以给标题加上精确板卡身份；相邻变体仍拒绝。
- 同一个授权数据库快照检查项目所有者，只读取本项目及平台当前已发布文本；私有索引沿用批准状态、停用哈希、板卡变体及来源规则。每个型号查询一次，优先保留手册、原理图、引脚、示例的类别多样性。
- 上限：补检索 8 秒且包含在原来的 90 秒总硬期限中；最多 24 条独立来源、每器件 4 条、32 KiB 清单。顺序 IO，不增加模型调用或自动重试；给保存留出时间。时间/容量/索引不可用均明确记为部分结果，不能当作全库无资料。
- 锁保存项目 ID、方案 ID、BOM 行/完整型号、检索版本、来源发布版本、位置、来源记录 SHA256、审核状态、摘录及规范化清单 SHA256。来源记录哈希对于已发布文本是知识版本哈希，对于私有索引是原始文件哈希；不是 ZIP 文件哈希。
- 模型返回的锁、引用、审核或价格字段不能替代服务端记录。自动索引资料始终注明“未人工复核”，不能据此宣称电气/引脚/驱动适配已验证。

## Agent 使用与失效

新回合先验证项目归属、项目/方案/BOM 绑定、清单哈希和当前发布版本。私有 Unix 接口 `/revision` 只读取活动索引及停用策略版本，不执行 FTS。没有网页公开入口，没有原件下载授权。

有效完整锁命中时，从项目锁的短摘录挑选至多 5 条、3200 字符上下文，避免重复全库 FTS；普通项目分析可以使用本项目已锁定器件。用户提出锁外的新精确型号时，走新检索，不能用旧器件替代。

资料更新/停用、活动索引/检索规则切换、索引故障、部分锁或哈希/绑定错误，均不复用锁。检索版本是保守的整体版本：无关共享资料发布也可能使锁过期，不做“部分来源仍有效”的乐观授权。新回合走当前受控检索并沿用现有上下文重置机制。派生方案视图不带失效摘录；生成前引用也不直接作为当前回合证据。历史方案/ZIP 及工作区旧文件保留，仅为历史记录，不是当前有效证据或持续访问授权。

历史任务没有锁时维持原有路径，不补造资料与哈希。要建立新版本锁可重新生成方案；本轮不增加后台自动刷新或重复计费生成。

## 数据与发布边界

锁复用既有 `design_jobs.result` JSON，不新增数据库表或迁移，`task.start` 沿用现有方案/检索载荷。新回合的派生方案独立校验哈希，既有 Runner 文件机制可读取；不是在 Runner 状态目录写文档。

发布顺序是先候选验证私有检索进程（新 `/revision` 与身份标签规则），再平台，最后方案 Worker；先让平台能核验新锁，再让 Worker 生成新锁。旧检索进程没有版本探测时只能降级为不可复用/部分检索，不假报成功。9/30 已完成该顺序及完整来源 overlay、PCB/Demo、备份、心跳与真实模型/Agent 工具回合验收。原件和索引文件未变。
